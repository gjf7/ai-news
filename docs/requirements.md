# 需求定义

## 产品范围

供个人使用，通过网站阅读完整相关新闻流，通过个人 Telegram 聊天接收精选提醒。没有注册、多用户订阅、推荐算法或公开内容分发。

## 新闻源

目标来源包括 Google News、Reddit、Hacker News、arXiv、TechCrunch、Financial Times、Wall Street Journal、The Economist、Semiconductor Engineering、EE Times、SemiWiki、IEEE Spectrum 半导体频道，以及 Bloomberg。

每个来源接入前验证实际可用的 API、RSS 或公开页面、使用条件及凭据要求。目标清单不等于已经验证全部可接入。不可用来源显示原因，不能使用模拟内容冒充真实采集。Google News 属于发现渠道，文章原始出版方另行保存，不能将聚合器与原始报道计作两个独立来源。

Bloomberg 数字订阅不直接接入账号、Cookie 或付费全文。第一版只使用来源提供的元数据与摘要，展示标题、摘要和原文链接，不抓取原文正文。若将来需要更深的分析，再单独验证付费全文采集与外部模型处理。

## 内容与阅读

- 主题支持 AI、半导体或两者同时；标识新闻、论文和社区讨论。论文默认只展示标题与摘要，不生成洞察。
- 保存原始标题、规范化链接、来源、原始发布时间、发现时间、可获得内容和内容范围。
- 同一文章去重，同一事件合并多个来源；不因同一公司或相同关键词就强行合并。
- 中文洞察包含标题、事实摘要、重要性、可能影响、可选观察点及来源引用。事实与推断分开。
- 内容范围只有标题与摘要两级，均由来源提供；不抓取原文正文。全部依据只有标题时不生成深入影响判断。
- 首页默认最近 24 小时，支持历史、主题和来源筛选，热点或最新排序。
- 模型失败时展示已采集的原始信息及待分析状态；旧洞察可以保留，但标记有新资料待分析。

## 更新

- 服务器每 30 分钟发起刷新，网页关闭不影响执行。
- 手动刷新立即创建或复用活动任务，显示真实阶段与数量，不伪造百分比。
- 自动与手动刷新共用业务入口，同一时间最多一个活动刷新。
- 手动刷新不移动自动时间表；错过多轮后只补最近一轮，不积压历史定时刷新。
- 页面自动检查更新版本；首页顶部自动加载新内容，翻页、滚动或展开阅读时保持位置并提示新增，用户点击后更新。此处实时指秒级发现后台结果，不是所有来源逐秒采集。
- 显示最近尝试、最近完整成功、部分成功、下一次自动刷新时间；无新增不是失败。

## Telegram

- 默认个人聊天，每轮最多 5 条精选新增事件；只推送本轮新出现或有实质进展、且重要性达到阈值的事件，无符合条件内容时不发送。未入选事件不累积到后续轮次。首次部署的第一轮不推送。
- 包含中文标题、简短洞察、原文与站内链接；站内详情仍需登录。
- 同一事件版本只推送一次，新增转载不自动算实质进展。
- 推送失败不影响网页内容发布。可重试错误（含超时、断连）自动有限重试；永久失败可在页面手动重试。
- 采用至少一次语义：极端情况下（发送成功后进程崩溃）可能重复一条消息，不会漏发已冻结的投递。

## 设置与运行

来源开关在网页修改。刷新间隔、推送开关及条数、模型名称与 API 地址、密钥均通过部署环境变量配置，修改后重启生效；网页只读展示非敏感配置及各密钥是否已配置，不回传密钥。支持简单个人密码登录。

数据持久化；记录每轮来源失败、分析失败、推送失败及重试结果。部署环境需要持续运行，并能访问所选新闻源、模型 API 与 Telegram。

## 验收

1. 关闭网页仍按计划刷新；自动和手动同时触发只产生一个活动刷新。
2. 单个来源失败，其他来源的结果仍可发布，页面准确展示部分成功。
3. 进程重启后，任务可恢复；已持久化内容不重复入库，已成功分析的相同输入不再调用模型。
4. 模型输出引用仅指向本次提供的证据，摘要依据与标题依据可区分。
5. 页面能发现后台更新；首页顶部自动加载，翻页或阅读时不强制回到第一页。筛选条件贯穿分页，列表按事件 ID 去重。
6. 同一事件版本不会进入两次投递；推送失败可见且可手动重试。
7. 未登录不能读取私有新闻、触发任务或修改来源开关；接口与日志均不泄露密钥。
